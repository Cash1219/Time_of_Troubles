## 能否让菜系越多、整栋建筑吞吐量越高？

可以按已启用的 PM **近似实现**：每道菜的「供应」PM 在 `building_modifiers.unscaled` 中提供少量 `building_throughput_add`。不同 PMG 的已启用 PM 都作用于同一栋建筑；供应量 PMG、现有接待 PMG 提供的吞吐量也计入。预计是**加法叠加**，不是每道菜相乘；具体显示值和商品计算顺序须进游戏验证。

原版生产方式定义允许 `building_modifiers.unscaled`，本模组咖啡厅接待 PM 与居酒屋接待 PM 已使用 `building_throughput_add`。一个 PMG 只能启用一个 PM，因此每道菜独立开关仍须各有「无／供应」PMG。

建议：每个菜系有一道**招牌菜**，开它给全建筑 **+2%** 吞吐量；该菜系另外两道各给 **+1%**。后两道可用 `unlocking_production_methods` 要求招牌菜已启用，以免只开附属菜却没有完整菜系。这个跨组要求的切换行为需游戏内验证。这样：

- 一个菜系只开招牌：+2%；三道全开：+4%。
- 六个菜系只开招牌：+12%；六个菜系、十八道全开：+24%。
- 增加**不同菜系**比只给同一菜系多加菜更快获得吞吐量，但多菜本身也略有收益。

示意脚本，仅展示机制，不是待写入代码：

```txt
pm_cafe_latte_on = {
    building_modifiers = {
        workforce_scaled = {
            goods_input_coffee_add = 2
            goods_input_milk_add = 5
            goods_output_luxury_drinks_add = 6
        }
        unscaled = {
            building_throughput_add = 0.01
        }
    }
}
```

牛奶用量仍为 5 的倍数；其他商品使用整数。每道菜产出暂定约 5～8 单位，少数招牌菜约 8～10 单位。单菜投入须使基础价商品毛利落在 30%～70%；例如示意拿铁咖啡 2×50＋5×20＝200，产出 6×60＝360，毛利 44.4%。吞吐量加成同时放大原料和产出，不会凭空省略牛奶消耗。

## 咖啡厅：六个菜系、十八道菜

| 菜系 | 招牌菜（+2%） | 其他两道菜（各 +1%） | 该菜系基础产量草图 |
|---|---|---|---|
| 经典咖啡 | 标准咖啡 | 摩卡、拿铁 | 高档饮品 8＋6＋6＝20 |
| 茶与乳饮 | 红茶 | 奶茶、热可可 | 高档饮品 8＋6＋6＝20 |
| 欧陆烘焙 | 饼干 | 蛋糕、苹果派 | 高档食品 8＋7＋7＝22 |
| 法式轻食 | 三明治 | 可丽饼、奶油汤 | 高档食品 8＋7＋7＝22 |
| 意式简餐 | 意大利面 | 焗烤、冰品 | 高档食品 8＋8＋7＝23 |
| 日式洋食 | 蛋包饭 | 章鱼烧、布丁 | 高档食品 8＋8＋7＝23 |

十八道全开时，不含吞吐量的基础供给为 **40 高档饮品＋90 高档食品，共 130 单位**。若供应量最高档仍给 +75%、菜系与菜品合计 +24%，且不选额外接待吞吐量，则预计为基础量的 **199%**，约 **259 单位**；与当前四个菜单组最高档合计 **260 单位**相近。若叠加现有最高接待 +15%，预计达 **214%**、约 **278 单位**。这些是倍率规划值，不是已验证的游戏结果。

新菜名中的「奶油汤」「焗烤」「冰品」「布丁」只是可选题材，须先定原料与年代门槛；若不想新增专用商品，可用谷物、杂货、肉、牛奶等现有商品。摩卡与可可的可可来源仍未定，不宜仅凭名称强行补科技。

## 居酒屋：六个菜单主题、十八道菜

| 主题 | 招牌菜（+2%） | 其他两道菜（各 +1%） | 主要商品方向 |
|---|---|---|---|
| 炉边旅店 | 炉边温酒 | 旅店炖菜、烤面包 | 烈酒、葡萄酒、杂货、肉、谷物 |
| 和风居酒屋 | 清酒与果酒 | 串烧、居酒屋小菜 | 烈酒、水果、肉、鱼 |
| 海鲜酒馆 | 烤鱼 | 海陆拼盘、果酒 | 鱼、肉、水果；拼盘可用少量牛奶 |
| 城市酒吧 | 招牌调酒 | 冷盘、奶油酒 | 烈酒、葡萄酒、水果；奶油酒用牛奶 |
| 东方茶酒 | 茶酒 | 茶点、热饮 | 茶、酒、谷物、糖 |
| 节庆宴饮 | 宴会酒 | 大盘菜、节庆甜食 | 酒、肉、鱼、杂货、糖 |

居酒屋每道菜暂以 **4～7 单位**为目标；十八道全开的基础产出先控制在现有最高档两组的 **100 单位左右**。由于牛奶 5 单位本身价值 100，含奶菜如果只产 4 单位，其他原料空间很窄，因此奶油酒、海陆拼盘等应取范围上端，不能机械地要求每道菜等量。该建筑需要独立完成逐菜配方表、工资和价格核算，再确定精确产出。

## 供应量 PM 与人员

- 前版的基础供应／批量备料／标准化供应／冷链供应四档 **0%、+25%、+50%、+75%** 可暂作上限草图。菜单越多又给吞吐量后，这四档可能需要降到 0%、+15%、+30%、+50%；最终由全开、半开和开局三种场景比较决定。
- 主力雇员留在供应量组，每道菜另加少量厨师或服务人员；这样开更多菜会提高工资，避免多菜吞吐量奖励没有成本。
- 现有咖啡厅接待组最高还有 +15%，居酒屋包间最高 +15%。供给 PM、菜品 PM 与接待 PM 同时加吞吐量时，必须合计试算；现有设备 PM 的投入折扣也会改变完整建筑的利润。
- 不建议给所有菜一样大的加成，否则 AI 很容易全开。即使按招牌 +2%、其余 +1%，基准价下所有菜若都赚钱，AI 仍可能偏好全开；可通过各菜固定人工、地方开局菜单和 AI 选择设定处理。

## 界面与实现成本

维持「每道菜可单独开关」时，咖啡厅和居酒屋各有 **18 个菜品 PMG**，加供应量、接待、设备/厨房，各约 **21 个 PMG**。代码可写，但建筑面板会很长。若游戏 UI 难用，可退到「每个菜系一个无／供应 PMG」，每个菜系代表三道小菜；这样只需六个菜系组，但玩家不能单独关掉其中一道菜。

本稿先确认**菜系数量、吞吐量机制和总量尺度**。逐菜投入产出、毛利、科技与开局 PM 映射在这三个决策确定后再写，不能直接将前版的大份配方缩小而不重算。
