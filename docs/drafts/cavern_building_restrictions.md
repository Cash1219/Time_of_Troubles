# 地穴地带建筑限制的实现

2026-09-28更新：用户转向“不限制常规建设、地穴人口稀少、特色建筑低人力”的方案。本文仅保留禁建方式的技术参考，不再作为当前实施方案；此前也没有启用这些限制。当前设计见gensokyo_population_resources_v1.md的“地穴低人口与自动化设施”部分。

当前只修复了地图归属与通道，没有在运行文件中启用建筑白名单。

原版 `common/buildings/buildings.md` 明确：`potential`、`possible` 和 `can_build` 均以州为作用域。`state_region = s:STATE_CHIREIDEN_CAVERN_ZONE` 可以判定地穴地带；原版运河等建筑使用同样的州判定。

若要让某建筑不在地穴地带出现，把以下条件加入其原有建筑定义的 `potential` 块。若原来没有该块，再新增：

```txt
potential = {
    NOT = {
        state_region = s:STATE_CHIREIDEN_CAVERN_ZONE
    }
}
```

若希望保留条目，并显示无法建设的条件，可使用 `can_build` 中的同样判定。所有原有条件必须保留。

只允许特定建筑的实现方式：对所有不允许的建筑附加上述排除条件；允许的建筑保留原条件。专用地下建筑还可以反过来用 `potential = { state_region = s:STATE_CHIREIDEN_CAVERN_ZONE }`，限定只能建在地穴。

注意：不能只写一个建筑名和这一小段就替换完整建筑定义，否则原来的成本、生产方式等字段会丢失。应从当前有效定义完整保留其他字段后追加条件。对已有 `potential` 或 `can_build` 要在同一块内追加，避免重复定义覆盖旧条件。

`buildable = no` 会全局禁建，不能用于只禁止地穴一州。省份 `impassable` 控制地图通行，不是建筑白名单。已有建筑和脚本创建的建筑需另行处理；这里说明的是通常建设入口的限制。

本部、各入口和绿洲可继续使用普通建设规则。专用地下建筑、能源生产方式和允许清单仍待确定，不应仅凭“少数特殊建筑”就自动放行所有矿井和工厂。
